# adhoc-ReflektIdentityUnification (RA2) — Implementation

Reflekt identity-plumbing unification: remove Reflekt's own `User`/auth, make an authenticated
retro participant's identity the Identity **`Person`**, scope Identity's global user-gate off Reflekt.

## Key Decisions
- **Step 1↔3 compile coupling.** Deleting the `User` type makes `ParticipantConfiguration.cs` (`HasOne<User>()`, `using Reflekt.Domain.Users`) uncompilable until Step 3 removes/repoints it (the plan assigns the Participant FK to Step 3, index to Step 7). Therefore the first green-build checkpoint is **after Step 3**, not after Step 1. Step 2 (additive, Identity-side) is independent and verified on its own. This is inherent to the plan's step split, not a deviation in content.
- **Seed sentinel introduced in Step 1.** `SeedOwnerPersonId` is specified by Step 7/Q5 but is introduced during the Step-1 seed-`User` removal because `Team.Create(..., user.Id)` cannot compile once `user` is deleted. Functionally identical to doing it in Step 7; sequencing only.
- **Step 4 TDD subject = pure predicate, not a `WebApplicationFactory` integration test.** The plan marks Step 4 `TDD: yes`, but this repo has **no web/integration test harness** — only `Fokus.Domain.Tests` (domain-unit; the csproj notes VSTest/Stryker constraints), and `testing.md` reserves `WebApplicationFactory` for endpoint integration while listing "endpoint routing" under *skip tests*. The risk-bearing logic in Step 4 is the **assembly discrimination** ("is the matched endpoint's declaring module excluded?"), which I extracted into the pure `ActiveUserGateScope.IsExcludedModule` and TDD'd directly (red→green, 4 tests). The HTTP plumbing that feeds it (`GetEndpoint()…EndpointType.Assembly.GetName().Name`) is thin wiring verified by the compiler + full build. This honors the plan's mechanism (Q4-A, unchanged) and the TDD intent (test the logic that can be wrong) without inventing an integration harness the project deliberately omits. **Discriminator is by assembly *simple name* (string), not `typeof(Reflekt marker).Assembly`** — because Identity must not reference Reflekt (CLAUDE.md: no cross-module project refs); the string keeps the modules decoupled and is equally Reflekt-exact. Reviewer: the full guest-not-401 / inactive-user-still-401 behavior is exercised end-to-end only at runtime (acceptance run), not by an automated integration test — flagged in Carry-Over.

## Deviations from Plan
- **First green-build checkpoint is after Step 3, not Step 1.** The plan splits the `User`-type removal (Step 1) from the `Participant`/claims repoint (Step 3), but deleting the `User` type makes `ParticipantConfiguration.cs` uncompilable until Step 3. Steps 1+2+3 therefore land together for the first full-solution green build (Step 2, Identity-side & additive, was independently verified green). No plan *content* changed — purely the build-checkpoint cadence, dictated by the compiler's coupling of the deletion and the repoint. Each step's edits are still recorded separately above.
- **`SeedOwnerPersonId` sentinel introduced in Step 1 instead of Step 7.** Step 7/Q5 specifies the sentinel constant, but `Team.Create(..., user.Id)` cannot compile once the seed-`User` block is removed in Step 1, so the constant was introduced in the same Step-1 edit. Functionally identical to Step 7's intent; sequencing only. Step 7's remaining work (the migration) was done in full.
- **Step 4 TDD subject is a pure predicate, not a `WebApplicationFactory` integration test** (see Key Decisions for full rationale). The plan's mechanism (Q4-A assembly-of-declaring-endpoint) is unchanged and the FE handle (`EndpointDefinition.EndpointType`) is confirmed by compile; only the *form* of the TDD test differs, because the repo has no web/integration harness and `testing.md` lists endpoint routing under skip-tests. The risk-bearing discrimination logic is fully unit-tested. Recorded as a medium Carry-Over for the reviewer.
- **Local-variable renames beyond the plan's letter (boy-scout, in-file).** In `SprintHub`, `GetSprintSummaryEndpoint`, `EditCardEndpoint`, `DeleteCardEndpoint` I renamed the owner-comparison locals `userId`/`resolvedUserId`/`cookieUserId` → `personId`/`resolvedPersonId`/`cookiePersonId` for value-space readability at the exact sites the critic flagged. The plan asked only to repoint the *claim read*; the local rename is an in-file clarity improvement on comparison sites, not a behavior change.
