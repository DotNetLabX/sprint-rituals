## Key Decisions

- **Explicit assignment for all 5 Save endpoints** (not `IRegister` + `req.Adapt(existing)`) — avoids Mapster edge case where adapting onto a tracked entity with `ComplexProperty` members can silently bypass change-tracking. Structurally equivalent to what the plan proposed; same result. Consistent with `SaveXraySettings` and `SaveCycleTimeBoundaries` pre-existing patterns.
- **`required` dropped from Person.FirstName/LastName/Email** — C# CS9032 forbids `required` + `private set` on the same property. With a `private Person() {}` ctor, external code cannot construct Person directly; the factory method is the only path. `required` was therefore redundant and removed. This is a safe deviation from the plan's "keep required" note — the encapsulation invariant is preserved via the private ctor, not the `required` keyword.
- **`private Person() {}` ctor added** — needed both because C# requires a non-private parameterless ctor when any `required` members are removed (and EF Core needs it for materialization). The plan said "add only if build proves it necessary" — the build proved it necessary (CS9032 fix required dropping `required`, which exposed the need for the explicit ctor).
- **Migration hand-edited** — EF generated drop+add for 5 columns; hand-edited to all-`RenameColumn` to preserve the singleton row's data values.
- **`private User() { }` added (fix cycle 1)** — `User` had no explicit ctor; C# emits an implicit public parameterless ctor in that case, allowing `new User()` to bypass `CreateFromPerson`. Added `private User() { }` to mirror the `private Person() {}` pattern. EF can still materialize via reflection; the factory stays the sole public creation path.
- **`AlterColumn` added to VO rename migration for `Sync_PlanningWindowDays` (fix cycle 1)** — `20260509203929_AddPlanningWindowDays` created the column with `defaultValue: 0`. The `RenameColumn` in the VO migration preserved that store default unchanged, leaving it mismatched against `HasDefaultValue(2)` in `AppSettingsConfiguration`. Added `AlterColumn` in the VO migration Up (defaultValue: 2) and Down (restored to 0) to align the store default with the model config, per `docs/conventions/ef-core.md` Migration Defaults rule.
